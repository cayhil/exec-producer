# Creating a Show

A show is a directory of JSON and prompt-text files — no Python required. The engine loads whatever
directory you point it at:

```bash
uv run exec-producer --data-dir path/to/your_show --list
# or persistently:
export EXEC_PRODUCER_DATA_DIR=path/to/your_show
```

Resolution order: `--data-dir` (or the env var) → the repo's `data/` directory if it exists → the
committed starter show at `examples/sunset_terrace/`. Two starters are committed: the ensemble
`examples/sunset_terrace/` and the solo `examples/night_signal/` (one host — see "Solo shows"
below). The fastest way to build a show is to copy whichever starter matches your format and edit:

```bash
cp -r examples/sunset_terrace my_show
uv run exec-producer --data-dir my_show --scene rooftop_welcome --lines 6
```

## The data contract

A show directory must contain every file below (the engine lists anything missing, all at once):

| File | What it is |
|---|---|
| `world.json` | Show identity, world text, intensity guide, models, provider keys, reliability |
| `cast.json` | The characters — one entry per cast member |
| `scenes.json` | Scene settings (name, premise, mood) |
| `episodes.json` | Episodes: ordered scenes with line counts and plot beats |
| `embodiment.json` | Physicality rules (base, per-gender, per-character, per-intensity) |
| `prompts/character_template.txt` | Master cast-member system prompt (placeholder-driven) |
| `prompts/director.txt` | Director system prompt (`__WORLD__` is injected) |
| `prompts/director_choice.txt` | Per-turn "who speaks next" request |
| `prompts/casting.txt` | Per-scene "who's in this scene" request |
| `prompts/production.txt` / `prompts/production_request.txt` | `--produce` image/video prompt generation |
| `prompts/judge.txt` / `prompts/eval_rubric.txt` | `--eval` judge system prompt and scoring rubric |
| `prompts/critical_rules.txt` | Output formatting rules every character receives |
| `prompts/tone_face_to_face.txt`, `prompts/tone_confessional_early.txt`, `prompts/tone_confessional_late.txt` | Tone rules by scene type and season stage |

Optional, per feature flag: `voices.json` (`--audio`), `visuals.json` (`--video`),
`prompts/planner.txt` (`--planner`).

Every loaded file's sha256 lands in the audit block of every saved output, so a script is always
traceable to the exact show files that produced it.

## world.json

- `show_name` / `show_slug` — console banners and output file prefixes (`scripts/<slug>_...`).
- `world` — the paragraph injected into every character and director prompt. This is your premise.
- `intensity_guide` — four text blocks (`low`, `medium`, `high`, `maximum`) describing the season
  arc's tone at each level. Both the director and every character receive the active one.
- `director_model` / `judge_model` — LiteLLM model strings. Keep them different: a director grading
  its own decisions is the classic LLM-as-judge self-preference trap.
- `content_rating.max_intensity` — optional hard cap applied to every run regardless of flags
  (the starter ships capped at `medium`). Remove the key for no cap.
- `provider_env_keys` — provider name → env var holding its API key.
- `reliability` — `num_retries`, `timeout_seconds`, and per-model `fallbacks`. Fallbacks are opt-in
  per model: give them to the director, not to cast members — a silent provider swap changes a
  character's voice mid-scene.

## cast.json

One entry per character. The key (e.g. `"jax"`) is the id used everywhere else.

- `name`, `emoji`, `tagline`, `gender` (`guy`/`girl` — drives embodiment defaults)
- `provider` — must match a `provider_env_keys` entry; `model` — the LiteLLM model string.
  Casting different characters on different models is the point: each character's dialogue is
  generated by their own LLM, and model personality bleeds through.
- `personality` — the character sheet. The starter's pattern works well: who they are, the
  contradiction under the surface, then core desire / core fear / how they love.
- `triggers` — list of things that reliably get a rise out of them.
- `relationships` — id → how they privately feel about that housemate.

A character needs its provider's API key set in `.env` to appear; the engine runs with whichever
cast members have keys (minimum two for an ensemble show, one for a solo show — see below).

## Solo shows (a cast of one)

A `cast.json` with exactly one character is a valid show — the committed starter
`examples/night_signal` (an overnight radio host) is the working example. Nothing else changes in
the contract; the engine adapts by cast size:

- The key gate relaxes to one cast key + the director key. No flag needed — a one-character show
  can only run solo. (To run a single member of a *bigger* cast, pass `--solo --cast <id>`.)
- Scene casting is skipped (there is nobody to cast), the cast sheet switches to solo phrasing,
  and the director's per-turn choice becomes pure beat direction: pacing, stage directions,
  emotional temperature. MONOLOGUE-style direction is the workhorse.
- Write the prompt files for one voice: night_signal's `director.txt` swaps speaker-picking rules
  for beat-pacing rules, its `tone_face_to_face.txt` becomes "the mic is hot" audience-address
  rules, and `critical_rules.txt` bans invented callers/co-hosts — the classic failure mode of a
  solo scene. Its `casting.txt` exists only to satisfy the contract (it documents this itself).
- Everything downstream is unchanged: episodes, `--planner` pacing, `--eval`, `--audio`,
  `--video`, telemetry, and the audit block all work identically on a solo run.

## scenes.json and episodes.json

Scenes are settings, not stories: `name`, `prompt` (the physical premise), `mood`. Episodes supply
the story: an ordered list of `{scene, lines, plot}` where `plot` is the beats that MUST happen —
physical activities the drama occurs during, not monologue topics. Sessions persist across an
episode's scenes: characters remember everything from earlier scenes, and the director casts each
scene after the opener.

## Prompt files

`character_template.txt` assembles each character's system prompt from placeholders
(`__WORLD__`, `__PERSONALITY__`, `__INTENSITY__`, `__TONE_RULES__`, ...). The tone files switch by
scene type — a scene whose name contains "confessional" gets the confessional rules (early vs late
by intensity). `critical_rules.txt` is the formatting contract (dialogue length, `[action]` vs
"speech" separation). `planner.txt` is the `--planner` arc-writer: its pacing rules (slow-burn,
phase vocabulary, the JSON schema) are yours to tune.

## Media files

`voices.json` maps character id → a persistent TTS voice id (`--audio`), plus defaults (TTS model,
inter-line gap). `visuals.json` sets per-character card colors and video defaults (`--video`);
without it, cards fall back to a built-in palette.

## Vlog mode (`--video --render-mode vlog`)

The vlog mode (solo-host generated footage with a persistent voice — see README for the full
tradeoff) reads two extra pieces of show data:

### Host reference images

Generate a set of 1-3 photos of your host once (any image tool), store them in the show
directory, and map them in `visuals.json` — they're attached to every Veo generation with the
host in frame, which is what keeps the host looking like the same person across clips:

```json
{
  "characters": {
    "marlow": {
      "color": "#232946",
      "reference_images": ["refs/marlow_front.png", "refs/marlow_side.png"]
    }
  },
  "vlog": {
    "aspect": "16:9",
    "price_per_second": 0.40,
    "max_clips": 12
  }
}
```

The `vlog` block (all optional): `aspect` (`16:9` default, or `9:16` — reference-image beats
then generate 16:9 and center-crop, a Veo API constraint), `price_per_second` (enables the
`--dry-run` cost ESTIMATE — check current Veo pricing), `max_clips` (hard cap per API-route run),
`duck_volume` (ambient bed level under voiceover lines), `veo_model`, `fps`, `video_codec`.
Speech-to-speech uses `sts_model_id` from `voices.json` defaults (default
`eleven_multilingual_sts_v2`).

### Delivery markers

Scene-JSON conversation lines may carry `"delivery": "on_camera"` (default) or `"voiceover"` —
audio treatment only; every line becomes a full video clip. Optional per-line `"shot"` (the
Veo shot description; a deterministic template fills in when absent) and `"host_in_frame"`
(default: true for on_camera, false for voiceover) refine what's on screen. The showrunner
skill writes all three when scripting vlog episodes.
